## 5. 핵심 판단

### D1

- 제목: REST 대신 gRPC 스트리밍 + 메시지 큐
- 부제: 대화는 기다리게 할 수 없었고, 분석은 수 초가 걸렸습니다
- 질문: 실시간 음성 대화와 무거운 AI 분석을 어떻게 함께 처리해야 할까요?

카드

- 버린 것: REST로 한 번에 응답
    - 왜 버렸나: 분석이 끝날 때까지 대화가 멈춤
- 고른 것: gRPC 스트리밍 + 메시지 큐
    - 왜 골랐나: 대화와 분석의 경로를 분리
    - 라벨: 선택
- 대가: 서버와 큐가 늘어 운영 지점 증가

펼치면 보이는 것

- 상황: 음성 대화는 바로 응답해야 했지만, BERT 기반 치매 징후·감정 분석은 CPU 연산이 무거워 수 초씩 걸렸습니다. 같은 FastAPI 프로세스에서 둘을 함께 돌리자 분석 모델이 GIL을 점유해 음성 대화가 끊겼습니다.
- 근거: 답변을 형태소 단위로 끊어 스트리밍하면 사용자가 기다리는 시간이 줄고, gRPC는 음성을 바이너리 그대로 AI 서버에 넘길 수 있어 REST처럼 파싱할 필요가 없었습니다. 이 두 가지를 근거로 REST 대신 gRPC를 제안했습니다. 분석은 대화가 끝나면 메시지 큐에 넘기고 바로 응답을 돌려주도록 AI 담당 팀원과 함께 설계했습니다.
- 트레이드오프: 서버와 메시지 큐가 늘어나 관리할 지점이 많아졌습니다. 형태소 조각은 순서가 꼬이면 TTS 음성이 뒤섞이기 때문에, 순서 보장과 사용자 증가 시의 처리량을 함께 고려해 Kafka를 선택했습니다.
- 결과: 분석은 별도 Worker 프로세스에서 처리되고, 분석 부하와 관계없이 대화가 이어지는 구조로 구현했습니다. 응답 속도는 아직 측정하지 않았습니다.

### D2

- 제목: 고정 TTL 대신 Sliding Expiration
- 부제: 어르신은 대화 사이 침묵이 길었습니다
- 질문: 대화가 길게 끊겨도 맥락을 어떻게 유지해야 할까요?

카드

- 버린 것: 고정 TTL 세션
    - 왜 버렸나: 침묵 중 만료되어 맥락을 잃음
- 고른 것: 입력마다 TTL 연장
    - 왜 골랐나: 대화가 이어지는 동안 세션 유지
    - 라벨: 선택
- 대가: 입력마다 Redis 쓰기가 한 번씩 추가

펼치면

- 상황: 대화 맥락은 Redis 세션에 TTL을 두고 저장했습니다. 그런데 어르신은 대화 사이 침묵이 길어서, 대화 도중 세션이 만료되고 LLM이 앞의 대화를 잃었습니다.
- 근거: 세션은 대화가 이어지는 동안만 살아 있으면 됐습니다. 대화 입력 이벤트가 들어올 때마다 TTL을 연장하는 인터셉터를 만들었습니다.
- 트레이드오프: 입력이 들어올 때마다 Redis에 쓰기가 한 번씩 더 생깁니다. 대화 빈도가 높지 않은 서비스라 감수할 수 있는 비용이라고 판단했습니다.
- 결과: 긴 침묵 뒤에도 대화 맥락이 유지됩니다.

### D3

- 제목: L4 로드밸런서 대신 클라이언트 Round Robin
- 부제: gRPC는 연결 하나를 계속 재사용했습니다
- 질문: AI 서버를 여러 대 띄우면 요청을 어떻게 나눠야 할까요?

카드

- 버린 것: K8s ClusterIP(L4)
    - 왜 버렸나: 재사용되는 연결 안의 요청은 나누지 못함
- 고른 것: Headless Service + gRPC 클라이언트 round_robin
    - 왜 골랐나: 클라이언트가 AI Pod를 직접 번갈아 선택
    - 라벨: 선택
- 대가: 분산 로직이 클라이언트 설정에 들어감

펼치면

- 상황: gRPC는 HTTP/2 연결 하나를 계속 재사용하기 때문에, AI Pod를 여러 개 띄워도 요청이 한 Pod로만 몰릴 수 있었습니다. 클러스터 단위 L4 로드밸런서는 이미 맺어진 연결 안의 요청까지 나누지 못합니다.
- 근거: 연결을 맺는 쪽에서 분산해야 한다고 판단했습니다. Headless Service로 CoreDNS가 모든 AI Pod IP를 돌려주게 하고, Spring Boot의 gRPC 클라이언트에 `round_robin` 정책을 적용하도록 설계했습니다.
- 트레이드오프: Istio 같은 서비스 메시 없이 해결하는 대신, 분산 방식이 클라이언트 설정에 묶입니다.
- 결과: 설계까지 마쳤고, K8s 배포 후 실제 분산을 확인할 예정입니다.
